## 0. 먼저 알아 둘 것 — 돈이 드는 명령과 안 드는 명령

| 명령 | 비용 | 언제 |
|---|---|---|
| `pytest`, `ruff`, `--replay`, `check_eval_regression.py`, `trace_report.py`, 화면 E2E `06-policy` | **0원** | 언제든 |
| `run_eval.py --record`, `run_policy_eval.py --record`, 앱에서 실제 분석·영향 분석 | **OpenAI 과금** (본인 키) | 프롬프트를 바꿔서 녹화를 새로 해야 할 때만 |

2026-10-11 녹화에 쓴 금액은 약 **$4.15**(호출 360건, gpt-4o 정가 가정)다. 녹화가 끝났으므로 아래 1~7장은 전부 0원이다.

> `--replay`는 OpenAI를 부르지 않는다. 키를 비워도 돈다(`OPENAI_API_KEY=`로 확인).
> 주의: `OPENAI_API_KEY=`로는 확인이 안 된다 — 설정이 `backend/.env`에서 키를 다시 읽는다.

## 2. R1 — "같은 입력이면 같은 숫자" 확인 (5분)

### 2-1. 판정 평가 4개를 키 없이 재생

```bash
for d in applicability_v1 holdout_v1 holdout_v2 holdout_v3; do
  REG_RADAR_EVAL_SNAPSHOTS=evaluation/ci/snapshots OPENAI_API_KEY= \
    python scripts/check_eval_regression.py --dataset evaluation/datasets/$d.json --model gpt-4o
done
```

기대 출력: 네 줄 모두 `✓ 기준과 같다 … 'misses': 0`.

- `REG_RADAR_EVAL_SNAPSHOTS` = 법령 원문 캐시 위치. 법제처도 부르지 않는다.
- `evaluation/baselines/*.json` = 기준 지표. 재생 결과가 한 글자라도 다르면 실패 → CI(`.github/workflows/backend-ci.yml`)도 같은 명령을 돈다.

### 2-2. 리포트 전체 보기

```bash
REG_RADAR_EVAL_SNAPSHOTS=evaluation/ci/snapshots OPENAI_API_KEY= \
  python scripts/run_eval.py --offline --replay --model gpt-4o --dataset evaluation/datasets/holdout_v3.json
```

맨 위 `▶ 출처:` 줄에 데이터셋 해시·프롬프트 버전·git 커밋·cassette 적중 수·토큰·추정 비용이 찍힌다. **숫자에는 항상 출처가 붙는다.**

### 2-3. 면접에서 설명할 버그 — "녹화했는데 재생이 안 됐다"

- 증상: holdout_v3를 녹화하고 재생하니 C4에서 9건 미스.
- 원인: 같은 조문을 다른 프로필로 보는 케이스들이 **같은 C3 프롬프트를 동시에** 불렀다. LLM은 같은 입력에도 다른 답을 줄 수 있어 두 답이 각자의 C4로 이어졌는데, 녹화에는 키당 하나만 남았다.
- 수정: 녹화 중 같은 키는 한 번만 부르고 나머지는 그 결과를 기다린다(`app/ai/cassette.py`의 `claim/resolve`). 테스트: `tests/test_cassette.py::test_녹화_중_같은_호출이_동시에_오면…`.
- 한 문장: "평가를 재현 가능하게 만드는 장치 자체에 동시성 버그가 있었고, 재생이 실패하면서 드러났습니다."

## 4. R3 — 사내 규정 영향 분석 (15분)

### 4-1. 흐름 한눈에

```
법령 조문 ─▶ 후보 검색(글자 2-gram TF-IDF, top-5)
         ─▶ C7 영향 판단 (CONFLICT / UPDATE_RECOMMENDED / ALIGNED / UNRELATED)
         ─▶ 코드 검증: 인용이 법령·규정 원문 양쪽에 실제로 있는가, 조문번호 위조, 허용 규정만 근거인가
         ─▶ C7b 반론 검토: "고칠 필요 없음"을 먼저 찾는 두 번째 판단
         ─▶ ACTIONABLE 이면 C8 개정 초안 → 코드 검증(근거 없는 수치·조문번호)
         ─▶ 승인 흐름: DRAFTED → IN_REVIEW → APPROVED | REJECTED (4-eyes, 해시 체인 감사 로그)
```

핵심 파일: `app/policies/service.py`, `prompts.py`, `workflow.py`, `postgres.py`, 규정집 `corpus/virtual_card_co_v3.json`(**가상**).

### 4-2. 봉인셋 결과를 키 없이 재생

```bash
REG_RADAR_EVAL_SNAPSHOTS=evaluation/ci/snapshots OPENAI_API_KEY= \
  python scripts/run_policy_eval.py --split sealed --replay
```

기대: `조치 재현율 100.0%`, `조치 정밀도 80.0%`, 케이스별 표. `--split dev`도 된다.

### 4-3. 봉인셋을 어떻게 썼나 (면접 핵심)

| 봉인셋 | 열기 전에 한 일 | 재현율 · 정밀도 | 결과 파일 |
|---|---|---|---|
| v1 (12건) | 라벨 확정 | 50% · 50% | `evaluation/results/20261011T085745Z_policy_impact_sealed_gpt-4o.txt` |
| v2 (15건) | v2 라벨 확정 → 인용 구간 분리, C7b 반론 검토 | 100% · 75% | `…091437Z_policy_impact_sealed_gpt-4o.txt` |
| v3 (11건) | **조문 전문을 읽고** 라벨 확정 → 허용 규정 규칙·검사 | 100% · 80% | `…094027Z_policy_impact_sealed_gpt-4o.txt` |

규칙: 봉인셋은 한 번만 연다. 결과를 보고 고친 것은 **다음** 봉인셋으로 잰다. v1·v2는 프롬프트가 바뀌어 지금은 재생되지 않는다 — 숫자는 위 결과 파일에 남아 있다.

설명할 실패 세 가지:
1. **형식 때문에 맞는 근거가 탈락** (v1): 모델이 조문 제목과 떨어진 항을 한 인용으로 이어 붙였다 → 구간별로 나눠 각각 대조(`segment_spans`). 원문에 없는 조각은 여전히 탈락한다.
2. **허용 규정을 '누락'으로 읽음** (v2 T7): "인가를 받아 … 연장할 수 있다"를 규정이 안 썼다고 보완 권고 → `is_obligation` 검사. 처음 만든 판별기는 "2년을 초과하지 아니하는 범위에서 … 사용할 수 있다" 같은 **허용형으로 쓴 한도**를 허용으로 오판해 진짜 충돌 2건을 놓쳤고, dev에서 잡아 "기본은 의무, 한도 표지 없는 '수 있다'만 허용"으로 고쳤다.
3. **내 라벨 실수** (v2 T2): '오조치'로 채점된 1건은 남녀고용평등법 제19조 ⑤항이 실제로 해당했다. 라벨을 정할 때 조문 앞부분만 읽었다. 공식 수치는 바꾸지 않고 `policy_impact_v3.json`의 `adjudication`에 메모만 남겼다.

## 5. R4 — 운영 지표 (5분)

```bash
# 시연용 trace 4행 넣기 (이 파일만 단독으로 돌린다. 전체 테스트는 정리하면서 지운다)
python -m pytest -q tests/test_ops_metrics.py
DATABASE_URL=postgresql://127.0.0.1:5432/regradar_test python scripts/trace_report.py --chains
DATABASE_URL=postgresql://127.0.0.1:5432/regradar_test python scripts/trace_report.py --validator
DATABASE_URL=postgresql://127.0.0.1:5432/regradar_test python scripts/trace_report.py --versions
```

- `--chains`: 체인별 호출·실패·평균 지연·토큰·**비용**. 규칙 검증(C6)은 `rules`로 따로 보이고 비용이 없다.
- `--validator`: Validator 거부 사유 순위와 "첫 시도 거부 → 재생성 통과" 비율.
- `--versions`: 프롬프트 버전(파일 해시 12자리)별 실패율·비용 — "프롬프트를 바꾼 뒤 나빠졌나"를 본다.
- 모든 API 응답에 `Server-Timing: app;dur=…` 헤더, 5초 넘는 요청은 WARNING 로그.
